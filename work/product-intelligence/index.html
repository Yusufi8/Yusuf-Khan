Business problem

When anyone can create products freely, the product master collects near-duplicates, inconsistent names and legacy codes. Buyers and sales staff then struggle to find the right item on purchase and sales orders, and cost history gets split across duplicates.

Solution

  • Guided product creation wizard instead of free-form product entry.
  • Category-based specifications so each category captures the same technical fields.
  • Configurable UID rules that build a product's unique ID from its category and specifications.
  • Duplicate detection with similarity checks, a review log, and overrides restricted to product stewards.
  • Alias, vendor code and specification search, with legacy internal references kept as aliases.
  • Cost and selling price history, with role-based price visibility.
  • Integration with Purchase, Sales, Inventory and Manufacturing, plus merge and migration wizards for cleaning up existing data.

My contribution

  • Developed the module: governance, UID rule, duplicate and price-history models; four wizards (creation, BoM, merge, migration); views, menus and dashboards.
  • Added security groups and access rules, including steward-only duplicate overrides.
  • Added a backend JavaScript extension so products can be found and added to order lines from the wizard.
  • Wrote automated tests and a migration plan for existing product data.

Functional workflow

  1. StartA user opens the guided creation wizard.
  2. SpecifyThey choose a category and fill its specifications.
  3. Generate UIDThe UID rule builds the product's unique ID.
  4. Check duplicatesSimilar products are flagged; only stewards can override.
  5. Create & useThe product is created and can be found by alias, vendor code or spec on orders.
  6. Track pricesCost and selling price changes are recorded.
